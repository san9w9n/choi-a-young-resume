## UI 개선 — 실측으로 확인한 것

1. word-break:keep-all
   원본에 없었습니다. 한글이 어절 중간에서 끊겨 320~430px 에서 특히 나빴습니다.
   overflow-wrap:break-word 를 같이 둬서 이메일 같은 긴 토큰은 여전히 끊깁니다.

2. <br> 강제 개행 제거
   원본 h1 과 푸터 h2 에 <br> 이 박혀 있어 폭이 바뀌면 어색하게 끊겼습니다.
   text-wrap:balance + max-width(ch) 로 바꿔 브라우저가 폭에 맞춰 고르게 끊습니다.

3. 한 줄 글자 수 상한
   --measure:42ch / --measure-wide:52ch 를 도입했습니다.
   .foot-note, .job .role/.detail/.org 는 상한이 없어 1280px 에서 60~84자/줄까지
   늘어났습니다 (Playwright 로 측정 후 발견 → 수정).

4. 터치 대상 44px
   .nav a 는 세로 패딩 9px + 14px 글자로 약 38px 이었습니다.
   --tap:44px 토큰을 만들고 nav/cta/hero-action/contacts 에 min-height 로 적용.

5. 모바일 본문 최소 크기
   430px 이하에서 14.5px·13.5px 이던 본문을 15px / 14px 으로 올렸습니다.

6. 앵커 이동 시 헤더 가림
   scroll-margin-top 이 92px 고정이었는데 모바일 헤더는 113px 입니다.
   --head-h 토큰(모바일 120px / 900px↑ 70px)으로 바꿔 섹션 상단이 안 가립니다.

## 리뷰(codex critic) 지적 → 수정

MAJOR 1  engines.node ">=20.9.0" 인데 check-copy.mjs 가 .ts 를 직접 import
         → Node 20.9 에서 ERR_UNKNOWN_FILE_EXTENSION 으로 게이트가 깨짐 (재현 확인)
         수정: engines 를 ">=22.18.0" 으로. Node 의 TypeScript type stripping 이
         22.18 부터 기본으로 켜집니다. 22.18.0 에서 실행해 통과 확인.

MAJOR 2  package.json 과 package-lock.json 불일치
         손으로 적은 캐럿 범위(react ^19.2.0, typescript ^5.9.4, eslint ^9.42.0,
         @types/node ^24.10.1)가 실제 설치본(19.2.8 / 6.0.3 / 9.39.5 / 26.2.0)과 어긋나
         npm ls 가 ELSPROBLEMS 로 실패. CI/Vercel 에서 재현 불가.
         수정: 실제 버전으로 맞추고 lock 재생성. npm ci 통과 확인.

MINOR 1  Career.tsx 의 `"role" in job` 좁히기 → CareerJob 타입(role?/detail? 옵셔널)
         정의 후 `satisfies CareerJob[]`. 컴포넌트는 job.role 로 단순 접근.
MINOR 2  Hahmlet weight 400/500/600/700 → 실제로 쓰는 500/600 만.
         (.quote::before 가 400 을 상속하고 있어 font-weight:500 을 명시)
MINOR 3  check-copy.mjs 가 site.description 같은 메타 문안을 아예 안 봄
         → checkMeta() 추가, 메타는 160자(검색 스니펫 기준) 상한.

# 2차 — 등장 애니메이션 + 읽을 분량 재축소

## 요청
"이력서 형식에 맞는 적당한 애니메이션" 과 "여전히 글이 좀 읽기 양이 많다".

## 애니메이션 — JS 0줄

CSS 스크롤 연동 애니메이션(animation-timeline)만 씁니다.
"use client" 컴포넌트도, IntersectionObserver 도 넣지 않았습니다.
페이지는 여전히 완전 정적 프리렌더(○ Static)입니다.

설계에서 제일 중요한 결정 하나:
  숨김 상태(opacity:0)를 평소 스타일이 아니라 키프레임 안에만 둔다.
이러면 애니메이션이 안 걸리는 상황 — 미지원 브라우저, 움직임 줄이기 설정, 인쇄 —
에서 요소가 처음부터 그냥 보입니다. "내용이 안 보이는" 사고가 구조적으로 불가능합니다.

  히어로   로드 시 1회 페이드인 (스크롤 전에 이미 보이는 자리라서)
  나머지   뷰포트 진입 시 12px 상승 + 페이드, entry 5%~60% 구간

리뷰에서 지적받아 고친 것: @supports 가 animation-timeline 만 확인하고 있었는데
animation-range 는 따로 지원될 수 있습니다. range 를 무시하는 브라우저에서는
등장이 제때 안 끝나 읽는 동안 글이 흐릴 수 있어, 둘 다 확인하도록 바꿨습니다.

문장 상한을 60자 → 45자로 조이고, check-copy.mjs 에 **본문 총량 상한**을 새로 넣었습니다.
문장을 하나하나 짧게 써도 개수가 늘면 결국 읽을 양이 늘기 때문에, 총량이 진짜 제어 장치입니다.

## 리뷰에서 가장 중요했던 교정 — 분량을 줄이려다 사실을 지웠다

1차로 1294자(-29%)까지 내렸는데, codex 리뷰가 원본 index.html 과 전수 대조해
축약 과정에 임상 사실이 지워진 것을 잡아냈습니다.

  "시야가 좁아 시각 추적이 어렵고"  → "시야가 좁고"        (시각 추적 소실)
  "허리·등 촉각 자극"              → "촉각 자극"          (부위 소실)
  "스스로 스윙 줄을 잡고"          → "스스로 줄을 잡고"    (무엇을 잡았는지 소실)
  "일정 시간 균형을 유지"          → "균형을 유지"        (지속 시간 소실)
  후기4 "그네와 구강 마사지, 관절 압박" → 관절 압박 소실
  후기5 "발만 쥐어도 몸부림", "자신감"  → 둘 다 소실
  후기6 "각성 조절과 시각 집중을 위한"  → 목적 소실
  사례 note 2번째 문장 (기록·설명이 신뢰로 이어졌다) → 통째로 소실

전부 되살렸더니 1365자가 되어 내가 정한 1300자 상한을 넘었습니다.
**상한을 1370 으로 올렸습니다.** 1294자는 사실을 지워서 만든 숫자였고,
분량 목표를 지키려고 사실을 지우는 건 본말 전도입니다.
감축률이 -29.0% → -24.6% 로 내려간 것은 그 대가입니다.

이 경위를 check-copy.mjs 상한 주석과 README "문안 길이" 에 남겨,
다음에 상한에 걸리는 사람이 같은 실수를 반복하지 않게 했습니다.

검증: 원본 index.html 의 핵심 사실 어휘 72개(기관명·평가도구·치료기법·변화내용·
자격·연락처)가 현재 content/resume.ts 에 전부 남아 있음을 스크립트로 확인. 누락 0.
